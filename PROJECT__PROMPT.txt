Act as a Principal Software Architect, Senior Backend Engineer, Distributed Systems Engineer, AI Infrastructure Engineer, Agent Systems Engineer, and R&D Engineer.

3. BYOK — Bring Your Own Key

BYOK is a first-class platform capability.

The Gateway must support users/tenants providing their own provider credentials.

The primary objective is:

ForgeAI should support real multi-provider experimentation without forcing the platform owner to pay for every user's LLM usage.

The architecture should distinguish between:

Platform-owned provider credentials
User-owned provider credentials

4. BYOK Request Flow

The conceptual flow is:

User
  |
  | provides provider key
  v
ForgeAI UI/API
  |
  v
Gateway
  |
  | identifies tenant/session
  |
  | resolves provider credential
  |
  v
Routing Engine
  |
  +------ Claude
  +------ OpenAI
  +------ Gemini


The Gateway is responsible for credential resolution.

AutoPR does not manage provider API keys.

5. BYOK Modes

Support multiple modes.

Mode A — Session-only

Recommended for the public portfolio demo.

User enters API key
       ↓
Key exists only for session/request lifecycle
       ↓
Gateway uses key
       ↓
Key discarded


Advantages:

Minimal security surface
No credential database
No long-term secret retention
Easy to explain
Good for public demos

Disadvantage:

User must provide the key again later.
Mode B — Encrypted account credential

Optional future capability.

If accounts are introduced:

User
 ↓
Encrypted provider credential
 ↓
PostgreSQL


Requirements:

Encryption at rest
Key-management strategy
Never log secrets
Never expose plaintext keys
Mask credentials in UI
Rotation
Revocation
Access control
Auditability

Do not implement this merely for the sake of complexity.

Mode C — Client-supplied credential

Allow the frontend/client to send a provider credential for an individual request.

For example, use a dedicated credential header or secure request mechanism rather than placing the provider key inside the normal LLM request payload.

The Gateway should:

Validate the request.
Resolve the selected provider.
Use the supplied credential for that call.
Never persist the plaintext key.
Never log it.
Never return it.
Clear it from request-scoped memory after use.
6. BYOK Security Requirements

Treat provider API keys as secrets.

Never:

log them
store plaintext keys
return them in API responses
put them in metrics
put them in exception messages
store them in Redis as ordinary cache data
store them in PostgreSQL plaintext


Ensure logs cannot accidentally contain:

Authorization headers

provider SDK request objects
HTTP client debugging output


Use secret redaction.

Discuss:
