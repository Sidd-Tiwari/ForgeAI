02Architecture and request lifecycleFrom tenant request to durable usage
Authenticate→Rate limit→Resolve BYOK→Route→Ledger

The Gateway owns tenant identity, request-scoped credentials, provider normalization, retries, mapped fallback, exact caching, cost attribution, and telemetry.

03Service responsibilitiesClear ownership across the platform
  • Gateway: normalized inference, BYOK, routing, cache, quota, and PostgreSQL usage ledger.
  • AutoPR: signed GitHub webhook ingestion, deterministic risk signals, and Gateway-bound review generation.
  • forge-eval: repeatable precision, recall, severity, and critical-miss quality gates.
04Security modelCredential, tenant, and runtime boundaries
  • Provider keys travel only in X-Provider-Key and remain request-scoped.
  • Prompts, provider keys, and PR diffs stay out of ledger metadata and metric labels.
  • Containers run non-root with read-only filesystems and no-new-privileges.
  • Public evidence includes immutable manifests, SPDX SBOMs, and Docker Scout results.
05Quality, delivery, and monitoringHow changes move toward production
  • Java and Python suites cover core endpoints, downstream failures, signatures, routing, and evaluation penalties.
  • Compose health checks gate service startup; Prometheus collects low-cardinality application metrics.
  • CI definitions validate tests, linting, Compose configuration, filesystem security, image builds, SBOMs, and provenance.
06Verified scope and limitationsHonest evidence boundaries
  • Locally proven: mock routing, BYOK attribution, cache isolation, tenant rate limiting, ledger writes, AutoPR simulation, and deterministic evaluation.
  • Still external: commercial provider calls, live GitHub comment posting, hosted CI execution, cloud deployment, and production SLO calibration.
  • Use README.md and the repository docs directory for diagrams, ADRs, runbooks, and detailed commands.
